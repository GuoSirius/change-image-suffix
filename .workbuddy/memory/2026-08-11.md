## 修复 GitHub release 说明与 CHANGELOG 不一致
- 现象：v2.2.0 的 GitHub release 说明过长（155+ 行），与 CHANGELOG 的 2.2.0 段落不一致。
- 根因：`.github/workflows/release.yml` 的 awk 抽取按标题 `#` 级数停止（`level <= target_level`），但 2.2.0 标题是 `##`(level 2)、旧版本是 `###`(level 3)，条件永不满足 → 脚本从不停止，把整个 CHANGELOG 都塞进 release notes。
- 修复：awk 改为「遇到下一个版本标题（`^#+ \[[0-9]`）即停止」，与 `#` 级数无关。本地验证：v2.2.0 抽 13 行（仅该版本 Features/Chores），v2.1.19 抽 6 行。
- 已提交 `b3fbc3f` 并推送到 gitee(origin) 与 github 双远端，修复对后续 release 生效。
- 已发布的 v2.2.0 release 本环境无 gh/令牌无法直接改写：已生成修正版 notes（/tmp/v2.2.0-release-notes.md，27 行，与 CHANGELOG 一致），需用户在 GitHub release 编辑页粘贴，或装好 gh 后 `gh release edit v2.2.0 --notes-file /tmp/v2.2.0-release-notes.md`。

## 修复右键菜单两个 bug（中文乱码 + 变更不自动生效）
- 现象：安装后 (1) 右键菜单未自动更新，看不到新增的「裁剪空白」等菜单变更；(2) 菜单中文/emoji 显示乱码。
- 乱码根因：子菜单 `.reg` 以 UTF-8 写入后 `reg import`，Windows 默认要求 UTF-16 LE + BOM，UTF-8 非 ASCII 即乱码；且主菜单经 `reg add /d "中文"` 也受终端代码页影响。
- 修复：把主菜单 + 子菜单合并进同一个 `.reg`，统一以 `'\uFEFF' + content` 的 `utf16le` 写入再 `reg import`；移除全部 `reg add` 主菜单调用。
- 不自动更新根因：`autoUpdateContextMenu` 仅当 `version.json` 里版本号与当前包版本不同才重装；新增「裁剪空白」属同版本内菜单结构变更，版本号不变 → 不触发。
- 修复：新增 `computeMenuSignature()` 对 `MENU_FORMATS`/`MENU_BASES`/版本号做 sha256 签名，存入 `version.json`；`autoUpdateContextMenu` 在「版本不同 OR 签名不同」时重装菜单。旧安装无 signature 字段 → 下次任意 `cis` 命令即自动重装（含乱码修复 + 新菜单项）。
- `MENU_FORMATS`/`MENU_BASES` 提升为模块级常量（供安装与自动更新共用）。`npm run build` 通过；已提交 `12927a1` 并推送到 gitee(origin) 与 github 双远端。
